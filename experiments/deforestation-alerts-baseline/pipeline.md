# Pipeline: Deforestation Alerts Baseline Analysis

This document describes the end-to-end flow for generating a policy-oriented
deforestation alert summary for a Places to Watch site. 

The pipeline was implemented and tested for Tesso Nilo National Park,
Indonesia (July 2023). An example output generated by this pipeline is
provided in `ai_summary_deforestationalert_tesso_nilo_july2023.md`

---

## Overview


The goal is to design and populate the prompt template, as provided in 
`artifacts/prompt_template.md`

The template requires the following variables: 
- {{DATASET_INFO}}
- {{REGION_OF_INTEREST}}
- {{BASELINE_DATA}}
- {{RECENT_DATA}}
- {{USER_NEEDS}} 


This prompt is fed into a frontier model. At the time of the experiment, we
used the latest anthropic claude model. 




```
AOI polygon + date range
        │
        ▼
[Step 1] GFW API queries  ──►  monthly alert tables
        │
        ▼
[Step 2] Baseline computation  ──►  BASELINE_DATA + RECENT_DATA
        │
        ▼
[Step 3] Prompt construction  ──►  structured prompt with 5 variables
        │
        ▼
[Step 4] LLM generation  ──►  policy narrative (~500–600 words)
        │
        ▼
[Output] ai_summary_deforestationalert_tesso_nilo_july2023.md
```

## Step 1: GFW API exploration (`src/explore_api.py`)

**Purpose:** Understand the GFW Integrated Alerts endpoint, validate the
reference data provided by the PTW team, and establish a working query pattern.

**Inputs:**
- `WRI_DATA_API_KEY` environment variable
- Tesso Nilo bounding box polygon (hardcoded in the notebook)
- Reference files in `data/`:
  - `API_query_alerts_tesso_nilo_july2023.txt` — the original API request
    shared by the PTW team
  - `JSON_response_alerts_tesso_nilo_july2023.txt` — the original response
    (9,791 lat/lon-only records)

**What it does:**
- POSTs a SQL query to the GFW Integrated Alerts endpoint:
  `https://data-api.globalforestwatch.org/dataset/gfw_integrated_alerts/latest/query`
- Retrieves: `longitude, latitude, gfw_integrated_alerts__date,
  gfw_integrated_alerts__intensity, gfw_integrated_alerts__confidence`
- Provides a reactive UI (date pickers + run button) for ad-hoc queries
- Validates the reference JSON and compares it to the richer query output
- Estimates disturbed area in hectares (each pixel ≈ 0.01 ha)

**Note on the reference data:** The PTW team's original query retrieved only
`latitude` and `longitude` (9,791 records). The notebook's richer query adds
date, intensity, and confidence fields, and returns 9,478 records for the same
period — the difference is due to the confidence filtering applied downstream.

## Step 2: Baseline computation (`src/baseline_analysis.py`)

**Purpose:** Build a temporal baseline for the AOI and analyze the target month
against it. The output of this step is the `BASELINE_DATA` variable used in
the prompt.

**Inputs:**
- Same API endpoint and polygon as Step 1
- Date ranges: 12 months preceding the target (Jul 2022 – Jun 2023) plus
  same-month comparisons from prior years (Jul 2020, Jul 2021, Jul 2022)
- Target month: July 2023

**What it does:**
1. `fetch_integrated_alerts_month()` — queries one calendar month at a time
2. `build_monthly_table()` — aggregates results:
   - Filters to `high` and `highest` confidence alerts only
   - Assigns pixel IDs (`lat,lon` rounded to 5 decimal places) for spatial
     tracking
   - Computes per-month summary: `pixels_total`, `pixels_high`,
     `pixels_highest`, `share_highest`, `intensity_mean`
3. Computes baseline statistics:
   - 12-month rolling median and mean
   - Same-month (July) year-over-year comparisons: 2020, 2021, 2022, 2023
4. Produces two Altair charts:
   - Monthly alert pixel counts with 3-month rolling median
   - Highest-confidence share over the same period

**Output (`BASELINE_DATA`):** A compact statistical summary describing typical
monthly counts, seasonal patterns, the baseline period, and the target month's
position relative to baseline. See `artifacts/prompt_variables.md` for the
actual value used.

## Step 3: Prompt construction

**Purpose:** Assemble the five prompt variables and construct the full prompt
for LLM generation.

The prompt uses a structured template with five `{{VARIABLE}}` placeholders:

| Variable | Source | How it was built |
|---|---|---|
| `DATASET_INFO` | GFW tech note | Compressed using ChatGPT; describes what integrated alerts are, confidence levels, caveats, and methodology |
| `REGION_OF_INTEREST` | Wikipedia | Describes Tesso Nilo: location, ecological significance, encroachment history |
| `BASELINE_DATA` | `baseline_analysis.py` output | Monthly summary statistics from Step 2; compact text format |
| `RECENT_DATA` | `baseline_analysis.py` output | Same process as baseline but for July 2023 only |
| `USER_NEEDS` | PTW collaboration document | Derived from discussion with the PTW team; describes target persona (policy analyst at international environmental NGO) and their information needs |

See `artifacts/prompt_variables.md` for the full content of each variable and
`artifacts/prompt_template.md` for the complete prompt template.

**Note on variable quality:** Populating the variables — especially
`DATASET_INFO` and `USER_NEEDS` — was the most time-intensive part of the
work. The quality of these variables has a greater effect on output quality
than the prompt structure itself.

---

## Step 4: LLM narrative generation

**Tool:** Claude Developer Workbench (Anthropic)

**Model:** Claude (specific version not recorded)

**Process:**
1. System prompt loaded 
2. User prompt template populated with the five variables by copy-paste
3. Prompt submitted; model first reasons through the data in a `<scratchpad>`
   block, then produces the final analysis inside `<analysis>` tags
4. Output reviewed and saved

**Output:** The full narrative is preserved in
`artifacts/ai_summary_deforestationalert_tesso_nilo_july2023.md`. It was shared with the PTW team
on January 21, 2024.

**Known limitation:** This step was performed manually in the Claude Workbench.
The variable population (copy-paste) is the main friction point for replication
across multiple sites. Automation is not recommended until the content quality
of the summaries is validated with domain experts.

## Replicating for another site

To run this pipeline for a different PTW site and target month:

1. **Replace the polygon geometry** in both notebooks with the new site's
   bounding box or polygon coordinates
2. **Update `REGION_OF_INTEREST`** with a description of the new site
3. **Run `baseline_analysis.py`** with the new date range to generate
   `BASELINE_DATA` and `RECENT_DATA`
4. **Update `DATASET_INFO`** if the new site uses a different alert dataset
5. **Review `USER_NEEDS`** — adjust if the target audience differs
6. **Submit the populated prompt** to the LLM

Steps 1–3 require code changes. Steps 4–6 are manual. Total effort estimate
for a new site: 2–4 hours, assuming API access and polygon geometry are
available.
